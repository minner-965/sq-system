# Phase 13 opportunity pool rules

Status: MC04 approved runtime rules (2026-09-08). Read PHASE13_BUSINESS_SCOPE.md first. The user approved the MC03 bands; all three positive bands become Active Business Opportunity without manual Opportunity Confirmation. Review flags are warnings only and never prevent pool membership.

| Band | Evidence requirement | Active pool |
|---|---|---|
| PRECISION | Verified identity, supported suitable business type and clear exact/approved equivalent category match, with no explicit exclusion | Yes |
| RELEVANT | Verified identity, suitable type and approved parent/adjacent/profile match, with no explicit contrary evidence | Yes |
| GENERAL_RELEVANT | Verified identity, acceptable commercial organization and supported broad commercial scope covering approved DPV categories; no explicit mismatch | Yes |
| EXPLORATORY | Plausible/partly established business identity or relevance, insufficient identity/category/type evidence, no explicit negative fact | No |
| NOT_SUITABLE | Explicit identity failure, unrelated industry, consumer individual, unverifiable social identity, disallowed business type or confirmed category mismatch | No |

An old NOT_SUITABLE label or a nonempty legacy exclusion string is not self-proving: inspect its reason and underlying records. Missing facts are not affirmative contradictions. OEM/manufacturer exclusions require actual supported type evidence, not absence of a buyer.

MC03 also discloses retained stored rejection decisions: REJECTED with a specific public-guide/non-company or OEM-only exclusion is a stored decision basis, not a newly independently verified website fact. If its underlying evidence reference is missing, flag that gap explicitly for review. Generic legacy status text never suffices.

Positive operating evidence must belong to the company and its own business, not a search target label, visitor question, supplier directory listing, third-party brand inside a report, or another company's blog profile. Broad wholesale/distribution wording alone does not prove DPV-category coverage where the same evidence establishes an unrelated main industry. Unresolved attribution conflicts stay EXPLORATORY. Do not use company-name blacklists.

Use current approved scopes and current/latest per-profile match records, retaining linked observation/source IDs. Explicitly check observation verification and source authority before using an existing scope resolver; its defaults are not evidence. Company-level aggregation takes the best supported profile, retaining all profile explanations and company-wide explicit exclusions. Never combine unrelated historical maxima into a fictional current result.

One row per company includes old decision/blocker, proposed band, category/type basis, explicit exclusions, independent contact/email state, active-pool decision and notes. Report all five totals, old-to-new matrix, market/profile/type groupings, up to 20 deterministic representatives per band, all promoted legacy exclusions and unexpected recommended downgrades. Representatives are not a new numeric ranking.

MC03 remains the historical read-only comparison. MC04 reuses that classifier and appends versioned opportunity-pool decisions without rewriting old scores, evidence, approvals or decisions. Existing ambiguous broad-scope records retain the approved bands and show review warnings; warnings do not fabricate supporting evidence. Contact readiness and email eligibility are separate projections. All V3 workspaces and exports use these same dimensions.
