## WP02 新数据模型与房源导入

新增迁移，建表（字段名英文，界面中文）：

- `sectors`：板块（office_retail / hotel_apartment / dining）。
- `properties`：房源。楼栋、楼层、单元号、类型（商铺 / 写字楼）、面积、挂牌租金、管理费、交付标准、配置（如“精装修3隔+15卡”）、可明火、可餐饮、排烟、平面图文件、状态（在租 / 意向中 / 已签约）。
- `hotel_room_types`、`apartment_units`、`dining_outlets`、`dining_packages`：酒店房型、公寓房型、餐厅和套餐（价格可空，资料后补）。
- `leasing_policy`：底价、起租年限、付款方式、递增率、免租期等；底价字段只对管理员返回。
- `companies`：统一企业档案（统一社会信用代码、名称、地址、经纬度、行业、规模、成立日期、来源）。
- `company_sector_tracks`：企业在各板块的跟进（阶段、负责人、意向房源/服务、意向价、下次跟进时间）。
- `activities`：跟进记录（电话、拜访、看场、微信、备注）。
- `users`、`roles`、`user_sectors`：沿用现有鉴权，加板块权限。

导入脚本 `scripts/hz/import-properties.mjs`：

1. 读 `E:\claude\训练数据\写字楼商铺\恒兆广场推租表08.15.xlsx`（ExcelJS）。
2. 处理合并单元格；楼层按单元号前两位重算（如 1307 → 13 层）。
3. “3栋”改为“1栋”；“1号楼”统一为“1栋”；“55暗”面积按 55 处理并在备注保留原文。
4. 同楼栋同单元号去重（1420、1116），58 行 → 55 套；输出清洗报告 `docs/hz/房源导入报告.md`。
5. 第 64 行整段备注拆成 `leasing_policy` 和项目信息。
6. 平面图 PDF 拆页转图片，挂到 13–15 层对应房源。
7. 酒店基本信息、鱼仔店基本信息写成种子数据。

**验收**：55 套房源入库，商铺 10 / 写字楼 45；导入报告列出每处修正；重复运行脚本结果不变（幂等）；非管理员接口拿不到底价。

## WP04 企业发现与评分

数据源适配器放 `src/discovery/providers/`，统一接口 `search(query) → companies[]`，所有调用记入现有用量记录表：

| 适配器 | 用途 | 演示阶段 |
|---|---|---|
| `amap` 高德 POI 搜索 | 恒兆广场 1–10 km 内企业、写字楼、园区 | 免费 Key，主力 |
| `baidu_search` 百度搜索开放接口 | 企业官网、新闻、招聘信号 | 每日 100 次免费 |
| `bocha` 博查网页搜索 | 同上，备用 | 有 Key 再开 |
| `company_registry` 天眼查/企查查 | 新设、迁址、规模 | 预留接口，不开 |
| `llm` DeepSeek / 智谱 | 从网页摘要提取需求信号、写推荐理由 | 低价接口 |

1. 恒兆广场坐标作为中心点；检索半径、行业关键词在设置页可改。
2. 评分规则（写进 `docs/hz/评分规则.md`，用现有 zen-engine 或代码实现）：距离、需求信号（新设 / 迁址 / 扩张 / 招聘）、规模与面积匹配、行业（不设黑名单，只对危化品等特殊业态加提示）。每个分数带来源链接。
3. 板块分流：同一企业可同时进入写字楼、酒店（差旅协议）、餐饮（团餐）候选。
4. 定时任务：每天一次检索（n8n 或 pg-boss 定时），新企业进“待复核”。

**验收**：在演示库里检索出至少 100 家周边企业；每家有分数、理由、来源；重复检索不产生重复企业；接口费用记录可查。

## WP05 招商客户管理与匹配

1. 企业详情页：基本信息、资料来源、各板块跟进卡片、跟进记录时间线。
2. 跟进阶段：待复核 → 待联系 → 已联系 → 看场 → 谈判 → 签约 / 放弃（放弃原因必填，用于积累“未成交原因”）。
3. 房源匹配：按面积区间、业态、预算推荐 3–5 套房源，可一键加入意向。
4. 意向价低于底价时提示招商人员（不显示底价数字），并通知管理员。
5. 看场预约和下次跟进提醒。
6. 权限：招商人员只看自己板块；企业基本信息共享。

**验收**：用演示数据走完“发现 → 复核 → 联系 → 看场 → 签约”；放弃时必须填原因；底价提示正确；越权访问返回 403。

## WP06 内容发布中心 + 抖音

结构：主服务负责素材、文案、确认和排期；`publisher/`（Python）负责真正去平台发布。

1. 素材库：上传图片/视频到本地存储（`data/media/`，不进 Git），按板块和场景打标签。导入 `E:\claude\训练数据\酒店公寓\酒店图片` 的 144 个文件，用视觉模型生成场景标签候选，人工修正。
2. 发布任务：选板块、主题、素材 → 调用模型生成标题、正文、话题标签（按平台风格，文字遵守 `CLAUDE.md` 第 4 节，不能有 AI 腔）→ 状态“待确认”。
3. 确认页：可改文案、换素材、设发布时间；确认后状态“待发布”。没有跳过确认的路径。
4. `publisher/`：Python 3.12 + Playwright；参考 social-auto-upload（MIT，先登记）的抖音上传流程，自己实现精简版或作为依赖引入。首次扫码登录后保存登录状态到 `publisher/state/`（不进 Git）。
5. 主服务和 publisher 通过数据库任务表通信（publisher 轮询“待发布”任务，回写结果、作品链接、失败原因）。
6. 频率控制：每账号每日上限、两次发布最小间隔，可在设置页调整。
7. 发布记录页：状态、链接、失败重试。

**验收**：用抖音测试账号完成 1 条图文、1 条视频的“上传 → 生成 → 确认 → 发布 → 回写链接”；未确认的任务不会被 publisher 拿到；登录失效时任务失败并提示重新扫码。
