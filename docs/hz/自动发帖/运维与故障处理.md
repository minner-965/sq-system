# 内容发布中心 运维与故障处理

适用对象：管理员、接手的开发人员或 AI 编程工具
运行电脑：minm（Simon 的电脑，常开），代码目录 E:\claude（仓库 github.com/minner-965/sq-system）
说明：具体命令以仓库中的 README 和 `docs/hz/` 为准。开发方在实现时把实际命令补到本文件对应位置（标有【实现时补充】）。

## 一、组成

| 部分 | 作用 | 位置 |
|------|------|------|
| 系统网站和接口 | 页面、数据库读写 | 主系统服务 |
| PostgreSQL | 数据 | 主系统数据库 |
| pg-boss 队列 | 定时发布、每小时检查消息、数据抓取 | 主系统内 |
| publisher（Python 3.12 + Playwright + social-auto-upload） | 抖音、小红书、视频号的发布和读取 | `publisher/` |
| 手机脚本（uiautomator2） | 朋友圈发布、在抖音 App 里回私信 | `publisher/phone_driver.py` |
| 登录状态 | 各平台 cookie | `publisher/state/`（不进 Git，要备份） |
| 素材文件 | 图片和视频 | 【实现时补充：素材目录】 |
| 模型接口 | 写文案、判断意图、起草回复 | 设置页配置服务商和 API Key |

## 二、首次部署（在 minm 上）

1. 电脑设置：
   - 电源选项设为“从不睡眠”
   - Windows 更新设置“活动时间”，避免自动重启
   - 系统服务开机自动启动【实现时补充：启动方式】
2. 安装依赖：Python 3.12、Node、PostgreSQL（或按仓库的 compose 文件启动），以及 Playwright 浏览器【实现时补充：命令】
3. 安装 social-auto-upload，使用功能需求中锁定的版本，不要直接装最新版
4. 安卓手机：
   - 打开开发者选项和 USB 调试，用数据线连接 minm，并在手机上点“始终允许这台电脑调试”
   - 初始化 uiautomator2【实现时补充：命令】
   - 手机设为常亮充电，关闭应用商店里微信的自动更新
   - 登录工作专用微信号
5. 在系统设置页填写模型服务商和 API Key，并设置月度用量上限
6. 在“发布账号”页逐个平台扫码登录
7. 用测试素材把功能需求第 10 节的验收项走一遍

## 三、日常故障处理

### 1. 登录过期（最常见）

- 现象：任务失败，账号状态变为“需重新扫码”
- 处理：管理员在“发布账号”页扫码，然后在失败任务上点“重新发布”
- 预防：每周看一次账号页，对超过三周没有重新登录的账号提前扫码

### 2. 手机未连接

- 先检查：数据线是否松动，手机是否有电，屏幕上是否弹出了“允许 USB 调试”
- 再检查：在 minm 上执行 `adb devices`，应能看到设备
- 如果微信自己更新了版本，脚本可能失效，按本节第 4 项处理

### 3. 模型接口失败

- 看设置页的错误信息：欠费就充值；服务商故障就切换到备用服务商
- 期间可以先手写文案和回复，发布和读取不受影响

### 4. 平台改版，脚本失效

- 现象：某个平台连续出现“页面元素未找到”，失败截图上的页面和以前不一样
- 处理：
  1. 在“发布账号”页暂停该平台，避免反复失败
  2. 抖音、小红书、视频号：先看 social-auto-upload 是否发布了修复版本，在测试环境升级并回归后再上线
  3. 如果开源项目没有修复，或者失效的是我们自己写的读取或手机脚本，交给开发人员。把失败截图和错误日志一起交过去，并告诉对方：“按 `自动发帖/功能需求.md` 修复 publisher 中 X 平台的 Y 功能”
  4. 朋友圈脚本失效、又急需发布时，可以临时开启 Open-AutoGLM 兜底，操作仍然需要人工确认。用完后关闭
- 不要做：不要关掉人工确认来赶进度，不要把发布频率调高

### 5. 账号被限流或封禁

- 立即暂停该账号的所有发布和回复任务
- 检查最近的发布频率和内容，降低频率
- 朋友圈账号被封时，不要用主号顶替

## 接入新平台或升级发布组件前要检查的事

发布组件（social-auto-upload）是别人的项目，里面有原作者按自己用途写死的默认动作。2026-10-11 就漏过一次：组件默认给视频加“内容由AI生成”“含AI生成内容”“来源转载”声明，两条实拍视频带着不符合事实的标注发了出去。

每接一个新平台、每次把组件版本往前提，先做完这几件再真发：

1. 把这个平台的上传代码从头读一遍（`publisher/vendor/social-auto-upload/uploader/<平台>_uploader/main.py` 里从 `upload` 开始的整条路），列出它会在页面上点的每一样东西：声明、标注、定位、合集、商品、同步到其他平台、可见范围。凡是我们没有明确要的，在 `publisher/apply_patches.py` 里关掉。
2. 找它有没有等键盘输入的地方（`input(`、读验证码文件）。发布程序不给它键盘，验证一律在浏览器窗口里做。
3. 先演练：表单填好、截图、不点发布，看截图里每个选项对不对。
4. 第一条真发的内容发完后，看这次上传的日志（`publisher/vendor/social-auto-upload/logs/<平台>.log`）里有没有我们不认识的动作。

## 发布程序的网络出口（直连通道）

这台电脑上的代理软件（Clash Verge，全局 + 虚拟网卡模式）把所有流量都送到国外再出去，国内网站看到的是美国机房的地址。平台看到账号在国外机房登录，会频繁要验证、把账号登出；政府网站直接拒绝访问。

不改代理软件的设置（改了 Claude 用不了）。发布程序自己带一个“直连通道”：

- `publisher/direct_proxy.py`：只在本机 127.0.0.1:7901 开一个小通道，把经过它的连接绑定到真实网卡上发出去，域名也从真实网卡去查。
- `publisher/hz_netpatch/sitecustomize.py`：让发布程序和它调用的发布组件打开的浏览器都走这个通道。
- 发布程序启动时自己带起来，每一轮检查通道还在不在。只有发布程序的浏览器走它，电脑上别的程序不受影响。
- “发布账号”页顶上有一行写着现在浏览器是怎么出去的。正常是“浏览器走本机宽带直连（……中国 广东 广州 ……）”；变成红字说明没走成，那时平台看到的又是国外地址。

检查：`publisher\.venv\Scripts\python.exe publisher\direct_proxy.py check`，应该显示真实网卡地址和一个国内地址。

通道起不来的常见原因：换了网络（网卡地址变了，重启发布程序即可）；真实网卡出去的本来就不是国内地址（这时不启用，照原样走）。网卡认错了可以在 `.env` 里写 `HZ_DIRECT_BIND_IP=网卡地址`。

## 手机到了以后怎么测

专用手机用来发朋友圈、在抖音 App 里回私信（电脑后台发的私信对方收不到）。两件事各有一个开关，默认关着；关着的时候手机上什么都不发。照下面的顺序做，每一步都在网页上看结果。

**准备手机（一次就好）**

1. 手机上：设置 → 关于手机 → 连点“版本号”7 次打开开发者选项；开发者选项里打开“USB 调试”（小米、OPPO、vivo 还要打开“USB 调试（安全设置）”）。
2. 关掉锁屏密码，屏幕超时设成最长，充电时保持亮屏。关掉应用商店里微信、抖音的自动更新。
3. 登录工作专用微信号，和发帖用的抖音号。
4. 用数据线连这台电脑，手机上弹出“允许 USB 调试吗”，勾“始终允许”，点允许。

**在网页上测**

5. 打开“发布账号”页，拉到最下面的“专用手机”。“连接”应显示“已连接”和手机型号，微信、抖音都显示“已安装”。显示“发布程序没有在运行”的，先双击 publisher 文件夹里的 start-publisher.cmd；一分钟内状态会刷新。
6. 点“测试一下微信”。手机会自己打开微信，进“发现 → 朋友圈”，截一张图，回到桌面，不发任何东西。半分钟左右出结果，点“看手机截图”核对截到的是朋友圈页面。
7. 点“测试一下抖音”。手机会打开抖音进“消息”页，截图，不发东西。
8. 测试没通过时，页面上写着卡在哪一步，截图也能点开看。常见原因：屏幕锁着、App 弹了升级提示、没有登录。处理完再点一次测试。

**真发一条试试**

9. 朋友圈：管理员在“专用手机”里点“发朋友圈”后面的“打开”。然后在“内容发布”里建一条朋友圈内容（文字加 1–2 张图），确认发布。到点后手机会自己发，发完朋友圈里能看到这一条，内容发布页显示“已发布”。
10. 私信：管理员点“在手机上回私信”后面的“打开”。用另一个抖音号（没有互相关注的）给发帖账号发一句私信，在“互动收件箱”点“立即检查”。这条私信的按钮会变成“确认，用手机发出”，确认后几分钟内手机会打开这段对话、核对对方说的话、发出回复，收件箱里显示“回复已由专用手机发出”。**一定要在另一个抖音号上看一下有没有收到**，收到了才算通过。
11. 任何一步出问题，先在“专用手机”里把对应开关关掉。关掉以后确认的私信回复会退回“复制到手机上回”，朋友圈内容不会发。

**出错时**

- 每次手机操作出错，截图和界面结构都存在 `publisher/state/diagnostics/`（文件名以 `phone_` 开头），朋友圈的失败截图在内容发布页也能点开。
- 提示“可能已经发出，不要直接重发”的，先到手机上看一眼，确实没发出再重新确认。
- 朋友圈失败一次会自动暂停这个账号，看过原因后在“发布账号”里点“恢复发布”。
- 微信、抖音改版后按钮名字可能变了：在手机停在出问题的那一页时运行 `publisher\.venv\Scripts\python.exe publisher\phone_driver.py dump 页面名`，把存下的截图和 xml 交给开发人员，改 `phone_driver.py` 顶上的按钮名字即可。改完先跑 `publisher\.venv\Scripts\python.exe publisher\tools\check_phone_flow.py`，全部通过再用。
- 在电脑上直接看状态：`publisher\.venv\Scripts\python.exe publisher\phone_driver.py status`；单独测试：`... phone_driver.py check wechat` 或 `check douyin`。
- 陌生人私信自动回复不走手机，仍然关着，要等确认对方能收到以后另外再定。
